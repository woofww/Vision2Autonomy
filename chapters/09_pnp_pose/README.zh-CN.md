# 第 09 章：PnP 相机位姿估计

[English](README.md) | [简体中文](README.zh-CN.md)

> 标定告诉我们相机怎样把光线变成像素；PnP 反过来利用已知的三维路标与二维像素，回答车辆此刻“在哪里、朝向哪里”。

![相机前进时路标投影如何变化](../../docs/assets/chapter09_pose_motion.gif)

## 学习目标

- 区分相机内参、外参、相机中心和位姿；
- 从投影方程推导 3D–2D DLT 线性系统；
- 理解为什么 DLT 的 3×3 块必须投影回合法旋转矩阵；
- 用重投影误差评价位姿，而不是只比较矩阵元素；
- 用 RANSAC 排除错误的地图地标匹配；
- 说明 PnP 在视觉定位、视觉里程计和自动驾驶中的位置。

前置知识：第 04 章的 RANSAC、第 05 章的针孔相机、第 08 章的内参与去畸变。

## 1. PnP 到底在求什么？

已知三类量：

1. 世界坐标中的三维点 `X = (X, Y, Z)`；
2. 它在图像中的像素 `x = (u, v)`；
3. 已标定的相机内参 `K`。

要求相机外参：

```text
R：世界坐标轴怎样旋转到相机坐标轴
t：世界原点在相机坐标中的位置
```

投影模型为

```text
s [u, v, 1]ᵀ = K [R | t] [X, Y, Z, 1]ᵀ
```

这里容易混淆的是：`t` **不是相机在世界中的坐标**。相机中心是

```text
C = -Rᵀ t
```

因为相机中心代入外参后必须落到相机坐标原点：

```text
R C + t = 0
```

## 2. 一个直觉：让虚拟相机重新解释观测

假设高精地图里记录了路牌角点、灯杆连接点和固定建筑角点。车辆图像中再次检测到它们：

```text
地图三维点 Xᵢ ──候选匹配──> 图像像素 xᵢ
                              │
                              ▼
                        猜测 R 和 t
                              │
                              ▼
                     把 Xᵢ 重新投影到图像
```

如果猜测的位姿正确，重投影点应该落在观测像素附近。PnP 的本质就是寻找一台虚拟相机，使它对地图的“所见”与真实图像最一致。

![PnP 对应、重投影与 RANSAC](../../docs/assets/chapter09_pnp_correspondences.png)

- 圆环：图像中的观测；
- 黑点：估计位姿后的重投影；
- 绿色：支持同一位姿的内点；
- 红色：被 RANSAC 拒绝的错误匹配。

## 3. 先用内参把像素变成相机光线

像素坐标包含焦距和主点。先左乘 `K⁻¹`：

```text
[x, y, 1]ᵀ ∼ K⁻¹ [u, v, 1]ᵀ
```

得到归一化相机坐标后，方程变为

```text
s [x, y, 1]ᵀ = [R | t] Xₕ
```

其中 `Xₕ = [X, Y, Z, 1]ᵀ`。这一步把“镜头参数”从位姿问题中剥离，只剩刚体变换。

## 4. 从投影方程得到 DLT

暂时把 `[R | t]` 看成一般的 `3×4` 矩阵 `P`，三行分别为 `p₁ᵀ、p₂ᵀ、p₃ᵀ`：

```text
x = (p₁ᵀ Xₕ) / (p₃ᵀ Xₕ)
y = (p₂ᵀ Xₕ) / (p₃ᵀ Xₕ)
```

移项得到两个线性约束：

```text
p₁ᵀ Xₕ - x p₃ᵀ Xₕ = 0
p₂ᵀ Xₕ - y p₃ᵀ Xₕ = 0
```

一个对应点贡献两行：

```text
[ Xₕᵀ   0     -xXₕᵀ ]
[  0    Xₕᵀ   -yXₕᵀ ]
```

把所有点堆叠成 `A p = 0`，对 `A` 做 SVD，最小奇异值对应的右奇异向量就是 DLT 解。矩阵有 12 个元素但只确定到全局尺度，因此至少需要 6 个 3D–2D 对应。

## 5. 为什么代码还要归一化三维点？

道路坐标可能以几十米计，而齐次坐标最后一维固定为 1。直接构造矩阵会让不同列的数量级相差很大，SVD 容易被数值尺度支配。

本章先把三维点：

1. 平移到质心；
2. 缩放到平均距离为 `√3`；
3. 求解后再把归一化变换乘回去。

归一化不改变几何问题，只改善条件数。它与第 04 章 Homography、第 05 章八点法中的归一化是同一个思想。

## 6. DLT 矩阵为什么还不是合法位姿？

噪声会使 DLT 得到的左侧 `3×3` 矩阵不完全满足旋转矩阵约束：

```text
RᵀR = I
det(R) = +1
```

代码对这个矩阵做 SVD：

```text
A = U Σ Vᵀ
R = U Vᵀ
```

这相当于寻找离 `A` 最近的合法旋转。三个奇异值的均值给出 DLT 的全局尺度，再用同一尺度恢复 `t`。

还有一个细节：齐次解 `P` 和 `-P` 表示同一投影。实现会先选择让旋转块行列式为正的符号，否则轻微像素噪声可能让结果翻转 180°。这个坑很隐蔽，但会让重投影彻底飞出图像。

## 7. 重投影误差才是共同语言

估计出 `R、t` 后，把每个世界点投回图像：

```text
x̂ᵢ = project(K, R, t, Xᵢ)
eᵢ = ||x̂ᵢ - xᵢ||₂
```

误差单位是像素。它同时反映位姿、三维点、内参和匹配是否协调，因此比“旋转矩阵差了多少”更接近视觉系统真正关心的结果。

![恢复的相机中心与道路地标](../../docs/assets/chapter09_pose_top_view.png)

教学实现只做线性初始化和旋转投影，没有非线性 Bundle Adjustment，所以带噪声时会保留少量系统误差。成熟系统通常继续最小化总重投影误差。

## 8. 为什么还需要 RANSAC？

一个路牌角点可能匹配到另一个相似角点；动态车辆上的特征也不应被当成静态地图地标。少数错误对应足以把普通 DLT 拉偏。

本章的 RANSAC：

1. 随机抽取小批对应点；
2. 用归一化 DLT 估计候选位姿；
3. 计算所有点的重投影误差；
4. 把误差低于阈值的点记为内点；
5. 选择内点最多、内点中位误差更小的模型；
6. 用全部内点重新估计。

六点是代数最小值；当数据足够时，代码用八点假设降低噪声敏感性。

## 10. 什么时候会失败？

| 场景 | 原因 | 对策 |
|---|---|---|
| 三维点几乎共面 | 通用 DLT 条件很差 | 使用平面专用 PnP/Homography，或加入不同高度地标 |
| 地标集中在小区域 | 对旋转和平移约束弱 | 让特征覆盖更大视野与深度范围 |
| 内参或去畸变错误 | 光线方向从一开始就错 | 先检查第 08 章标定与重投影误差 |
| 动态物体特征过多 | 违反静态世界假设 | 语义过滤、运动一致性与 RANSAC |
| 纯线性 DLT 精度不足 | 没有直接最小化像素误差 | 用非线性优化精化 `R、t` |
| 地图坐标尺度错误 | 平移尺度随地图一起错误 | 检查三维地图单位与基准坐标系 |

## 11. 与自动驾驶的联系

- **高精地图定位**：把车道标志、灯杆和建筑地标与地图关联，恢复车辆六自由度位姿。
- **视觉里程计**：上一帧三角化出的三维点与当前帧像素形成 PnP，连续位姿组成行驶轨迹。
- **AR 导航与调试**：位姿正确时，地图车道、导航箭头和传感器投影才会稳定贴在真实道路上。
- **多传感器融合**：PnP 估计可作为定位滤波器的视觉观测，与 IMU、轮速和 GNSS 共同约束车辆状态。
- **安全监控**：内点率骤降、重投影误差突升，往往意味着遮挡、动态干扰、标定漂移或地图不一致。

PnP 给出的是感知系统的**几何自我定位**，不是完整的自动驾驶定位方案。下一章会把匹配、三角化与 PnP 串成视觉里程计，讨论尺度、漂移和轨迹评估。
