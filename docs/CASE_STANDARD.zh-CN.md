# 案例文档规范

[English](CASE_STANDARD.md) | [简体中文](CASE_STANDARD.zh-CN.md)

Vision2Autonomy 中的案例只有在其他学习者无需阅读未说明的源码，也能复现并理解结果时，才算真正完成。

## 必须包含的内容

每个案例必须提供以下内容：

1. **学习目标**：说明案例要解决的问题和所需前置知识。
2. **算法原理**：解释公式、假设、关键步骤和设计选择。
3. **可执行代码**：提供确定性的脚本、模块入口或 CLI 命令。
4. **输入参考**：文档中明确展示实际使用的图片或数据集样本。
5. **过程证据**：展示有助于理解算法的中间结果，而不只是最终图。
6. **输出参考**：展示由当前提交代码实际生成的预期结果。
7. **参数说明**：记录参数取值、单位、默认值、影响和调整方法。
8. **结果分析**：解释图中现象、产生原因以及常见失败模式。
9. **自动化验证**：至少有一个测试覆盖示例的关键执行路径。
10. **复现命令**：提供可以从仓库根目录直接执行的完整命令。

## 图片资产规则

- 参考图片统一保存在 `docs/assets/` 并提交到 Git。
- 每张派生结果图都必须有仓库内的脚本能够重新生成。
- 使用随机数据时必须固定随机种子。
- 生成图片不得经过人工修饰后再提交。
- 文件名必须能够识别所属章节和用途。
- 使用外部数据集或图片时必须记录来源、许可证和必要署名。
- 中英文文档共享同一组结果图片，避免不同语言展示不一致的实验。

## 推荐章节结构

```text
学习目标
前置知识
原理与公式
实现步骤
执行命令
输入图片
中间结果
最终输出
参数表
结果分析
局限与改进方向
测试方法
```

## 完成定义

代码能够运行并不代表案例已经完成。只有当文档命令可以重新生成展示结果、自动化测试通过、图片与当前实现一致，并且读者能够解释结果及其局限时，该案例才算完成。
