# Case documentation standard

Every Vision2Autonomy case is considered complete only when another learner can
reproduce and understand it without reading undocumented source code.

## Required files and evidence

Each case must provide:

1. **Learning objective** — the question being answered and prerequisites.
2. **Algorithm explanation** — equations, assumptions, and implementation steps.
3. **Executable code** — a deterministic script or CLI command.
4. **Input reference** — the exact image or dataset sample used in the document.
5. **Process evidence** — meaningful intermediate images, not only final output.
6. **Output reference** — the expected result generated by the committed code.
7. **Parameters** — values, units, defaults, and guidance for changing them.
8. **Result analysis** — what is visible, why it occurs, and known failure modes.
9. **Automated verification** — at least one test covering the example path.
10. **Reproduction command** — a command runnable from the repository root.

## Asset policy

- Reference images live under `docs/assets/` and are committed to Git.
- A committed script must regenerate every derived image.
- Random examples must use an explicit seed.
- Generated images must not be manually retouched.
- Filenames identify their chapter and purpose.
- Dataset licensing and attribution must be recorded when external images are used.

## Definition of done

A chapter is not complete when its code merely runs. It is complete when the
documented command regenerates the displayed result, the tests pass, and the
reader can explain the result and its limitations.
